# SPEC — vgpu-player: источники и HTTP(S)-воспроизведение

План нового цикла: **этапы 1–6**. Прошлый цикл 0–13 (локальные файлы) принят,
его история — `git log` и теги `v0.1.0`…`v0.3.0`. Текущее состояние —
`docs/CURRENT_TASK.md`, разбор mpv — `docs/URL_LOGIC_MPV.md`.

## 1. Рамки

Делаем: HTTP(S) VOD по прямой ссылке (MP4/MKV/WebM/MP3), `file://`,
перемотку через HTTP `Range`, асинхронное открытие, `Loading`/`Buffering`,
понятные ошибки, подготовку контракта под HLS.

Не делаем: DRM, YouTube и подписанные страницы, DASH, live/ABR, субтитры,
офлайн-кэш, авторизацию. HLS — только этап 5; до него `.m3u8` даёт
`UnsupportedHls`.

## 2. Архитектура

```text
UI ── Command::Open(Source) ──► поток ядра
                                   │ Source → ReaderFactory
                                   │   FileReader / HttpReader
                                   ▼
                     FFmpeg: input_from_stream_with_interrupt
                                   │
                     ┌─────────────┴─────────────┐
              аудиодекодер                 видеодекодер
                     │                           │
              rodio (аудио-часы)         очередь кадров ──► UI
```

### 2.1 `Source`

```rust
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Source {
    File(PathBuf),
    Url(String), // http:// или https://
}
```

- `Source::parse(&str) -> Result<Source, SourceError>`: `http(s)://` → `Url`;
  `file:` в формах `file:///C:/…`, `file://C:/…`, `file:/C:/…`,
  `file:C:/…`, `file://localhost/…`, `file://server/share` → `File`;
  остальное — путь.
- `Source::from_os_string(OsString)` — для CLI и drag-and-drop; не-Unicode
  путь не портится. URL распознаётся по ASCII-префиксу схемы (`file:`, не
  только `file://`).
- `file:`: percent-декодирование (`%20`), на Windows `/C:/…` → `C:/…`,
  `file://server/share` → UNC, `localhost` — локальная машина.
- `display()` — для UI; `log_name()` — для логов и ошибок (query/fragment
  заменяются на `?…`, чтобы не светить токены).
- `file_name()` — последний сегмент; расширение используется как `Hint` FFmpeg.
- `is_network()`, `is_hls()` (`.m3u8`, без учёта регистра, и у файлов).
- `From<PathBuf>`, `From<&Path>`, `From<&PathBuf>`. URL с пробелами,
  управляющими символами или `user:pass@` отклоняется.

`SourceError` — публичный `thiserror`-тип с текстом для CLI/UI.

### 2.2 `MediaReader`

```rust
pub(crate) trait MediaReader: Read + Seek + Send {
    fn len(&self) -> Option<u64>;
    fn is_seekable(&self) -> bool;
    fn hint_name(&self) -> Option<&str>;
}
```

- `FileReader` — `std::fs::File`, всегда seekable.
- `HttpReader` — HTTP/1.1 с `Range` (см. 2.3).
- `VideoDecoder::open(&Path)` сохраняется; для обоих источников добавляется
  `VideoDecoder::open_source(&Source)`.

Требования к `Read`/`Seek` для `StreamIo`:

- `Read` блокирующий; `WouldBlock`/`TimedOut` наружу не отдаются.
- При отмене — `io::ErrorKind::Interrupted`; `StreamIo` переиспрашивает его
  и завершает работу по interrupt-колбэку.
- `Ok(0)` — EOF. `SeekFrom::End` используется для `avio_size`; при
  неизвестной длине возвращается ошибка.
- Позиция меняется только после успешного ответа сервера.
- HLS-читатель — исключение: `len = None`, `is_seekable = false`,
  `Seek` не используется. Время → сегмент считает `HlsSource`, а
  перемотка VOD идёт через `Media::seek`/`seek_time` (§2.7).

### 2.3 `HttpReader`

Один читатель на дорожку (звук и видео независимы).

**Запрос:** `GET`, `Range: bytes=<pos>-`, `Accept-Encoding: identity`,
`User-Agent: vgpu-player/<version>`, `Accept: */*`.

- 206 — `Range` поддержан, длина из `Content-Range`.
- 200 — `Range` не поддержан: читаем последовательно, `seekable = false`;
  длина — из `Content-Length`, если она есть (chunked — неизвестна).
- 3xx — только http/https, не больше 10.
- 4xx — сразу ошибка; 5xx и обрыв — повтор.
- `Content-Type` сохраняется; `text/*` при провале FFmpeg даёт `NotMedia`.
- `Content-Encoding: gzip/br` — понятная ошибка (мы просили `identity`).
- Ответ 206 сверяется с запрошенным диапазоном.

**Чтение:** один загрузчик и один кэш блоков на источник (§2.6); звук и видео
читают из него своими курсорами. Блок 256 КиБ, кэш 64 МиБ, read-ahead
8 МиБ. Последовательное чтение идёт из кэша; `Seek` внутри кэша бесплатен,
иначе кэш сбрасывается и загрузчик идёт с нужного блока. Источник без `Range`
читается одним последовательным потоком; перемотка вперёд — перезапуск и
пропуск до 64 МиБ, иначе `NotSeekable`.

**Счётчики:** живут на кэше — запросы и байты считаются один раз на источник,
без двойного учёта двух дорожек; медленные чтения — ожидание курсора.

**Надёжность:**

- DNS/connect 5 с, одно чтение 2 с, простой без данных 15 с, 5 повторов
  с backoff 0.2…3.2 с.
- Отмена: `Arc<AtomicBool>`; `Stop`/`Open`/`Drop` прерывают чтение за
  ≤ 2–3 с. DNS/connect не прерываются, но ограничены 5 с.
- `Pause`/`Seek`/`SetVolume` во время чтения применяются после его возврата
  (до 2 с) — известное ограничение одного потока ядра.
- Причина ошибки источника хранится в `Arc<Mutex<Option<HttpFailure>>>`;
  каждый читатель переводит её в свой слот, а декодер заменяет безликий
  `invalid data` FFmpeg на понятный текст.
- Память: кэш ≤ 64 МиБ на источник плюс сами декодеры; отдельных окон по
  2 МиБ у читателей больше нет.

**TLS:** в текущей vcpkg-сборке FFmpeg нет TLS-бэкенда, поэтому `https`
через него не работает. Нужен свой клиент (см. §8).

### 2.4 Декодеры

- **Видео** — `StreamIo::from_read_seek` +
  `input_from_stream_with_interrupt`; перемотка через
  `Input::seek` → `MediaReader::seek`.
- **Звук локального файла** — Symphonia, при отказе FFmpeg.
- **Звук по URL** — только FFmpeg: `Symphonia::MediaSource` требует
  `Read + Seek + Send + Sync`, а сетевой читатель таким не является.
- **`probe_tracks`** — только для файлов. Для URL контейнер и кодеки берутся
  из открытых декодеров (`container_name()`, `codec_name()`), поэтому на URL
  два соединения, а не три.
- **`.m3u8`** — `UnsupportedHls` до `Media::open` и
  `VideoDecoder::open_source`.

### 2.5 Что нельзя ломать

- Ведущие часы — аудио; для видео без звука — монотонный таймер.
- Очереди ограничены. Для сети очередь звука — 32 блока (~0,75 с), иначе
  блокирующее чтение видео опустошает звук; при провалах — prefetch-поток
  или раздельные декодеры.
- `epoch` отбрасывает кадры до перемотки/открытия.
- Пул BGRA-буферов и `recycle_frame`.
- UI не блокируется на IO.

### 2.6 Общий кэш (этап 4)

Один загрузчик и один кэш блоков на источник; у звука и видео свои курсоры
чтения.

- Блок **256 КиБ**, кэш **64 МиБ** (несколько минут 1080p); read-ahead — до
  8 МиБ впереди самого дальнего курсора.
- Загрузчик идёт последовательно от конца закэшированного. Вытесняется
  любой блок, целиком лежащий позади всех курсоров; если таких нет, загрузчик
  ждёт (backpressure), а не рвёт нужное чтение. Исключение — курсор стоит в
  «дыре» (нужного блока нет, а в кэше только блоки впереди): тогда жертвуется
  самый дальний блок, иначе загрузчик не сможет докачать пропущенное.
- `Seek`: целевой блок в кэше — бесплатно; иначе кэш **не сбрасывается**:
  загрузчик переключается на целевой блок, `fetch_pos` возвращается к курсору.
  Прыжки демуксера (MP4: в конец за `moov` и обратно) не качают файл заново;
  второй курсор, идущий сразу за первым, попадает в уже скачанное.
- Отмена запроса (перемотка или закрытие) не выбрасывает уже полученные
  байты: неполный блок остаётся в кэше, следующий запрос продолжает с его
  конца.
- Источник без `Range`: кэш качает последовательно с начала, `Seek` —
  `Unsupported` (как сейчас); дублирования трафика больше нет.
- Ошибка сети хранится в кэше и будит все курсоры; каждый `HttpReader`
  переводит её в свой слот `HttpFailure`.
- Счётчики сети — общие на источник: без двойного учёта запросов и байт.
- Память кэша ограничена сверху; тест проверяет, что она не растёт.

### 2.7 HLS (этап 5)

Утверждён вариант **B** (2026-11-23): свой HLS-клиент на `ureq`, FFmpeg
получает готовый поток байтов через `StreamIo`. Проверка 5.0: в связанном
vcpkg-FFmpeg нет `https`/`tls`, но есть демуксеры `hls`, `mpegts`, `mov`.

#### Вход и выбор варианта

- Вход — `http(s)://…/index.m3u8`; допускается master или media плейлист.
  Локальные `.m3u8` (`Source::File`) в этапе 5 не поддерживаются:
  `UnsupportedHls`.
- Master: один вариант без ABR — максимальное разрешение ≤ 1080p, затем
  `BANDWIDTH`. Варианты дедуплицируются по `URI`: один видео-URI может
  повторяться для разных аудиогрупп (Apple: 8 URI × 3 группы).
- Аудио: атрибут `AUDIO` + `#EXT-X-MEDIA:TYPE=AUDIO`. Предпочитается
  `DEFAULT=YES`, AAC (`mp4a` в `CODECS`) и 2 канала. Запись без `URI`
  означает muxed-аудио внутри варианта. Ссылка `AUDIO` на несуществующую
  группу — ошибка `Hls`.
- Если вход — media-плейлист без master, он считается muxed-источником.

#### Playlist

- Парсер `hls.rs`: `#EXTINF`, `#EXT-X-TARGETDURATION`,
  `#EXT-X-MEDIA-SEQUENCE`, `#EXT-X-ENDLIST`, `#EXT-X-MAP`,
  `#EXT-X-BYTERANGE`, `#EXT-X-KEY`, `#EXT-X-DISCONTINUITY`, `#EXT-X-MEDIA`,
  `#EXT-X-PROGRAM-DATE-TIME`; относительные URL, query, `..`/`.`.
- Неизвестные теги игнорируются; ошибки несут номер строки и причину.
- `#EXT-X-KEY` с `METHOD` ≠ `NONE` в первой версии — понятная ошибка
  (`Hls`/`UnsupportedHls`); AES-128 — отдельный подшаг.
- `#EXT-X-PROGRAM-DATE-TIME` нужен для выравнивания demuxed live-дорожек;
  при его отсутствии — старт по live-edge и PTS.

#### Источник и дорожки

- Один `HlsSource` на открытый URL:
  - **muxed** — один media-плейлист, оба декодера читают его;
  - **demuxed** — video-плейлист варианта + audio-плейлист rendition.
- `open_reader(source, track, cancel, shared)` получает `Track::Audio` или
  `Track::Video`; `HttpSource` трек игнорирует. Это расширяет этап 4, но
  не меняет его поведение.
- Для muxed оба читателя используют один `TrackSource` и один набор
  сегментов: каждый сегмент скачивается один раз. Для demuxed — по
  загрузчику на дорожку.
- `NetworkStats` агрегирует запросы, байты, slow/retries по дорожкам;
  строка `cache: MB` для HLS не показывается.
- Память: хранится окно сегментов, а не весь VOD; лимит ~32 МиБ на дорожку
  с вытеснением позади всех курсоров.

#### Чтение сегментов

- FFmpeg получает **последовательный виртуальный поток**: MPEG-TS —
  конкатенация сегментов, fMP4 — `#EXT-X-MAP` перед сегментами.
- Не-seekable источник (HLS, HTTP без `Range`) отдаётся FFmpeg через
  `StreamIo::from_read` без seek-колбэка: иначе mov-демуксер на live fMP4
  ищет конец/размер и бесконечно читает сегменты. Перемотка HLS всё равно
  идёт через `Media::seek`.
- `#EXT-X-BYTERANGE` — обычный `Range`-запрос.
- Сегменты качает пул фоновых prefetch-воркеров: окно вперёд —
  **16 секунд эфира** от самого отстающего читателя (`#EXTINF`), но не
  больше 8 сегментов (защита от коротких/нулевых `#EXTINF`). Для muxed —
  8 соединений, для demuxed — по 4 на дорожку (всего 8), у каждой дорожки
  свой пул и своё окно. Читатель не ждёт сеть, если сегмент уже скачан,
  а при ожидании выставляет `Buffering`. Так одно медленное соединение
  CDN не ограничивает полосу: без пула live на Twitch давал сотни `drop`.
- Воркеры поднимаются лениво — при регистрации первого читателя. До
  первого чтения качать нечего, а серия `open` + `seek_time` иначе успевала
  скачать начало VOD.
- Синхронная загрузка (prefetch не успел или не запущен) помечает сегмент
  `in_flight`, поэтому один сегмент не качается дважды.
- Зашифрованные сегменты prefetch пропускает: их обрабатывает читатель и
  возвращает понятную ошибку.
- Первая сетевая ошибка запоминается в `TrackSource` дважды: в слоте для
  декодеров (они забирают его один раз при отображении ошибки) и в
  «липком» слоте для планировщика. Из-за этого prefetch и новые читатели
  не перезапускают запросы к сломанному источнику после того, как ошибка
  уже отдана UI.
- Повторы, таймауты и отмена — как у `HttpLoader`; ошибка хранится в слоте
  и заменяет `invalid data` FFmpeg.

#### Перемотка

- `MediaReader` для HLS не обещает байтовый `seek`: виртуального размера
  конкатенации до скачивания нет.
- VOD-перемотка — по времени: `Media::seek` пересоздаёт декодеры с
  читателями, стоящими на сегменте с целевым временем, затем декодеры
  отбрасывают сэмплы до точной позиции. Часы, `SeekHint` и `Seeked`
  работают как сейчас. `Media::seek` для HLS не вызывает `Input::seek`;
  точность опирается на непрерывные PTS сегментов.
- Live: `seekable = false`, `duration = None`.

#### Live

- `live = true`, если выбранный video- или audio-плейлист без
  `#EXT-X-ENDLIST`; иначе `live = false`.
- Старт — с хвоста окна (последние сегменты, достаточные для прайминга).
- Плейлист обновляется раз в `TARGETDURATION` (не чаще 1 с); чтение идёт
  за `MEDIA-SEQUENCE`, исчезнувшие сегменты пропускаются,
  `#EXT-X-DISCONTINUITY` сбрасывает декодер.
- Для demuxed live окна видео и аудио могут не совпадать: старт
  выравнивается по `#EXT-X-PROGRAM-DATE-TIME`/live-edge, а расхождение PTS
  компенсируется сдвигом видео (по образцу `initPTS` в hls.js).
  `HlsSource::video_pts_shift_ms()` применяется в `VideoDecoder` к PTS
  кадра.
- `#EXT-X-DISCONTINUITY`: читатель повторяет init fMP4, а признак разрыва
  передаётся декодерам и сбрасывает их состояние (`flush`) перед
  следующим пакетом.
- Live fMP4: абсолютные PTS (tfdt) могут начинаться не с нуля; для live
  HLS `VideoDecoder` вычитает `AVStream.start_time`, чтобы кадры
  синхронизировались с аудио-часами от 0. Для VOD и файлов опора — 0.

#### Ограничения

- LL-HLS (`#EXT-X-PART`, `#EXT-X-PRELOAD-HINT`, `#EXT-X-SKIP`) не
  поддерживается.
- AES-128 и другие `#EXT-X-KEY` — отдельный подшаг.
- YouTube watch URL не поддерживается: плееру нужен HLS master. `yt-dlp -g`
  даёт отдельные media-плейлисты (video-only/audio-only), а не master.

Вариант A (HLS-демуксер FFmpeg) отклонён: обходит наш HTTP-слой, кэш и
счётчики, а два декодера могут дать двойной трафик.

## 3. Контракт

### 3.1 Команды и события

| Команды UI → ядро                | События ядро → UI           |
| -------------------------------- | --------------------------- |
| `Open(Source)`                   | `Ready(Box<MediaReady>)`    |
| `Play`                           | `PositionChanged(Duration)` |
|                                  | `Seeked(Duration)`          |
| `Pause`                          | `Buffering(bool)`           |
| `Seek(Duration)`                 | `Stats(SyncStats)`          |
| `SeekRelative { forward, step }` |                             |
| `SetVolume(f32)`                 | `Spectrum(SpectrumBars)`    |
| `Stop`                           | `Ended`                     |
|                                  | `Error(String)`             |

`SeekRelative { forward, step }` считает цель в ядре от текущей позиции:
удержание `←`/`→` не зависит от задержки `PositionChanged` в UI. Подряд
идущие шаги одного направления ядро склеивает в одну.

`Seeked` подтверждает перемотку: UI держит ползунок на цели и игнорирует
запоздавшие `PositionChanged`, пока не придёт это событие.

`DurationKnown` удаляется: длительность приходит в `Ready`.

```rust
#[derive(Debug, Clone, PartialEq)]
pub struct MediaReady {
    pub media_info: MediaInfo,
    pub video_info: Option<VideoInfo>,
    pub duration: Option<Duration>,
    pub seekable: bool,
    pub live: bool, // true для live HLS (без #EXT-X-ENDLIST); иначе false
}
```

Для HLS:

- `duration` — VOD: сумма `#EXTINF` video-плейлиста; live: `None`.
- `seekable` — `true` только для VOD (обе дорожки не live); live — `false`.
- `live` — `true`, если video- или audio-плейлист без `#EXT-X-ENDLIST`.
- `media_info.audio` — из audio-rendition для demuxed (кодек, каналы,
  частота из открытого декодера).

### 3.2 Открытие

- `Player::open(source) -> Result<Player, PlayerError>` только запускает
  поток и ставит `Open`; ошибка `Result` — только `StartEngine`.
- Результат открытия — `Ready` или `Error`; ошибка не убивает поток.
- `Player::video_info()`/`media_info()` удаляются.
- `Stop`, новый `Open` и `Drop` взводят флаг отмены до отправки команды.
- Ошибка звукового устройства приходит `Error`, поток живёт дальше.

### 3.3 `VideoPlayer`

- `PlaybackState::Loading`; `play`/`toggle_playback`/`restart`/`seek` в нём
  игнорируются.
- `open` ставит `Loading`, сбрасывает кадр и метаданные; превью первого кадра
  только для `Source::File` (`.m3u8` не превьюится).
- По `Ready`: `seekable` сохраняется, состояние `Ready`; `autoplay` → `Play`.
- Звук стартует вместе с первым кадром: после `Ready` и после `Seek` вывод
  звука ждёт, пока ядро покажет первый кадр новой позиции. Иначе звук
  уходит вперёд, а кадр остаётся старым.
- После конца звука позиция в UI ведётся видео-таймером (хвост видео), а не
  застывшими аудио-часами: слайдер должен дойти до конца вместе с картинкой.
  За `duration` позиция не выходит: после `Ended` таймер останавливается.
- По `Error`: `Failed`, кадр и текстура сбрасываются, иначе превью скроет
  текст ошибки.
- `seek` при `!seekable` или `duration = None` команду не отправляет.
- `retry()` повторяет тот же `Source`; при `EngineGone` создаёт новое ядро.
- Геттеры: `source()`, `seekable()`, `buffering()`; `path()` — только для файла.

### 3.4 CLI и `run_app`

- `run_app(Option<PathBuf>)` сохраняется; для URL —
  `run_app_source(Option<Source>)`.
- `VideoPlayer::{create,open}` принимают `impl Into<Source>`.
- `vgpu` (release-бинарник пакета `player-app`): `Source::from_os_string`,
  снимаются внешние ASCII-кавычки и парные типографские (`“…”`, `‘…’`,
  `«…»`); `https://…` и `file:` не считаются путём; без аргумента
  открывается пустое окно.
- `player-cli`: первый аргумент — `Source`; метаданные из `Ready`, без
  второго декодера; `--decode-frames` — через `open_source`.
- Установщики Inno и MSI добавляют каталог приложения в пользовательский
  `PATH` (`HKCU\Environment`, `REG_EXPAND_SZ`), без UAC и идемпотентно;
  удаление убирает только свою запись. После установки в новой консоли
  работает `vgpu "https://…"`.
- Уже открытые консоли сохраняют старое значение `PATH`; установщик
  рассылает `WM_SETTINGCHANGE`, новый процесс видит изменение.
- URL передаётся в кавычках: в `cmd` символ `&` разделяет команды, а в
  PowerShell `(` и `“…”` — синтаксис самого PowerShell, поэтому
  `vgpu file:///…(ft.…)` не запускается (виноват не плеер). Годятся
  `vgpu '<URL>'`, `vgpu "<URL>"` или `vgpu --% <URL>`.
- Портативная сборка `PATH` автоматически не меняет;
  `register-associations.cmd path` добавляет/убирает запись вручную.
- `vgpu` в release — GUI-подсистема: консольный запуск возвращает
  приглашение сразу и не печатает stderr; ошибки видны в окне плеера.

## 4. Ошибки

Тексты для файлов не меняются; для URL используется `Source::log_name()`.

| Ситуация                              | Вариант             | Текст                                       |
| ------------------------------------- | ------------------- | ------------------------------------------- |
| нет файла / прав                      | `OpenFile`          | `не удалось открыть <path>: <io>`           |
| пустой файл                           | `EmptyFile`         | `файл <path> пуст`                          |
| пустой ответ URL                      | `EmptySource`       | `по ссылке нет данных: <url>`               |
| 404/403/5xx                           | `HttpStatus`        | `сервер вернул 404 для <url>`               |
| таймаут/DNS/TLS                       | `Network`           | `сеть: <причина>`                           |
| не медиафайл                          | `NotMedia`          | `по ссылке не медиафайл: <url>`             |
| нет `Range`                           | `NotSeekable`       | `источник не поддерживает перемотку: <url>` |
| HLS: плейлист/вариант/сегмент         | `Hls`               | `HLS: <причина>: <url>`                     |
| HLS: шифрование/LL-HLS/локальный файл | `UnsupportedHls`    | `HLS пока не поддерживается: <url>`         |
| URL до этапа 3                        | `UnsupportedSource` | `источник пока не поддерживается: <url>`    |
| кривая строка                         | `SourceError`       | `не похоже на URL или путь: …`              |

`Hls` используется для ошибок плейлиста, варианта и сегмента; `target` —
исходный master/media URL (query скрывается `log_name`), причина содержит
номер строки или URL сегмента в том же скрытом виде. `UnsupportedHls` —
только для того, что ещё не реализовано (AES-128, LL-HLS, локальный
`.m3u8`), чтобы это отличалось от сетевой/форматной ошибки.

## 5. UI

- **`Loading`** — «Загрузка…»; кнопки Play/паузы и слайдер неактивны.
  Спектр не рисуется, пока нет `Ready`.
- **`Buffering`** — плашка «Буферизация…»; кадр остаётся, управление доступно.
- **Live HLS** — плашка `LIVE` в правом верхнем углу кадра, слайдер
  серый (`seekable = false`), `Seek` игнорируется; у VOD слайдер и
  `SeekHint`/`Seeked` работают как у файла.
- **Demuxed HLS** (отдельный audio-rendition) визуально не отличается:
  звук подключается вторым читателем, UI по-прежнему видит один источник.
- **Перемотка HLS VOD** может пересоздать декодеры на границе сегмента;
  до прихода `Seeked` возможна плашка «Буферизация…», ползунок уже на цели.
- **«Открыть…»** в меню — панель с «Файл» / «URL». «Файл» — родной диалог,
  «URL» — поле ввода: символы, `Backspace`/`Delete`, `←`/`→`/`Home`/`End`,
  `Ctrl+V`, `Enter` — открыть, `Esc` — закрыть. Пока поле открыто, горячие
  клавиши плеера не работают.
- **Кнопка Play без файла** по-прежнему открывает родной диалог файла;
  меню «Открыть…» — путь к URL.
- **Информация о файле**: для URL — ссылка, без размера; метаданные из `Ready`.
- **Оверлей статистики**: `fps · drop · lag`; для URL — ещё две строки:
  `net: req · MB · slow N (s) · retries M` (+ `restarts K`, если были)
  и `cache: MB` — сколько байт сейчас занято в общем кэше (отдельно от
  трафика `net`). Для HLS `net` складывает видео и audio-rendition, а
  `cache: MB` не показывается (блочного кэша у сегментов нет).
- **Слайдер**: при `!seekable` или `duration = None` серый и не перематывает.
- **Громкость**: значок в панели открывает выдвижную панель над рядом
  кнопок. Внутри слева — значок mute (клик выставляет 0 %), ползунок с
  бегунком и процент справа; над ползунком процент показывает значение под
  курсором. Панель закрывается по повторному клику по значку, `Esc`, клику
  по кадру или открытию меню; колесо мыши по-прежнему меняет громкость
  шагами 1 %.
- **Окно**: минимальный размер 560×315 — ниже таймлайн и время уже не
  помещаются.
- **Перемотка**: ползунок сразу встаёт на цель и стоит, пока ядро не дошлёт
  `Seeked`; в это время может быть плашка «Буферизация…».
- **Клик по кадру**: один — пауза/продолжение, два — полный экран (повторный
  двойной клик, `Esc` или `F` возвращают окно). Одиночный клик срабатывает с
  задержкой `DOUBLE_CLICK_DELAY` (~250 мс), чтобы первый клик пары не ставил
  видео на паузу.
- **Ошибка**: текст в кадре + «Повторить».
- **Drag-and-drop** — только файлы.
- **Автоскрытие панели** прячет заодно курсор мыши; любое движение
  мыши возвращает курсор и панель (скрытие/возврат делает платформа через
  `Platform::hide_cursor_until_mouse_moves`). Работает только при включённой
  настройке «Автоскрытие панели» и во время воспроизведения.

### Этап 4 — трафик и общий кэш

Сейчас каждый читатель качает файл сам. Замер на этапе 3 (клипы ~2,6 МБ):
MP4 — 5,18× файла (видео 6,79 МБ + звук 6,79 МБ, по 8 запросов),
MKV — 3,58× (4,68 + 4,68 МБ, по 5 запросов); на реальном файле 25,3 МБ —
2,6×. То есть трафик дублируется дважды: по дорожкам и из-за перемоток
демуксера с отброшенным prefetch.

Подэтапы и редакция решений — в `docs/CURRENT_TASK.md`.

- [x] **4.0** Замер по дорожкам (✅ есть: видео = звук = весь файл).
- [x] **4.1** `cache.rs`: общий кэш блоков и один загрузчик; фейковый
      источник в тестах, без HTTP.
- [x] **4.2** `HttpReader` работает через кэш; счётчики — на источник;
      источник без `Range` тоже без дублирования.
- [x] **4.3** Память и устойчивость: любая вытесняемая память не больше
      64 МиБ, backpressure; `Seek` сохраняет блоки; seek и два курсора под
      тестами. Замер MP4/MKV — 1,00×.
- [x] **4.4** Приёмка: трафик ≤ 1,2× файла на MP4/MKV, `drop` не хуже,

Приёмка: ✅ MP4/MKV на `http` качаются один раз (25,3-МБ клип — 1,00×);
на реальной ссылке `bytes` в статистике ≈ размеру файла; память на плато
(194–205 МБ, кэш 64 МиБ); воспроизведение, перемотка/пауза/звук и закрытие
во время загрузки не хуже этапа 3 — подтверждено владельцем 2026-11-21.

## 7. Тесты

- `Source`: URL, `file://`/`file:` (диск/UNC/`localhost`/`%20`),

- Отмена ≤ 2–3 с; `open` без блокировки UI.
- `.m3u8` до 5.0 → `UnsupportedHls`; после 5.0 — HLS VOD/live под тестами.
- HLS-парсер: master/media, `#EXT-X-MEDIA`/`AUDIO`, относительные URL,
  byte-range, fMP4, ключи, `PROGRAM-DATE-TIME`, битые строки; реальные
  тексты Apple/YouTube/Twitch из `target/hls-tests` (если есть).
- HLS VOD muxed (TS) и demuxed (fMP4/TS): длительность, seek через
  переоткрытие, пауза, `Ended`, `Seeked`.
- Сквозные тесты — `crates/player-core/tests/hls.rs`: настоящий `Player`,
  сервер на `127.0.0.1`, ассеты `ffmpeg`; live-сервер дописывает окно.
  10 тестов: VOD muxed/demuxed (TS/fMP4), live TS/fMP4 (включая PTS-сдвиг
  1000 с), ошибки, трафик и prefetch на медленном сервере;
  `StreamIo::from_read` для не-seekable сторожится live fMP4-тестом.
- HLS live muxed и demuxed: `live = true`, `seekable = false`, обновление
  окна, старт с хвоста, без паники при закрытии.
- HLS трафик: muxed — один запрос на сегмент; demuxed — по одному на
  дорожку; `NetworkStats` суммирует; без двойной загрузки.
- HLS ошибки: 404/500 плейлиста и сегмента, пустой сегмент, битый
  плейлист, неизвестный `AUDIO`, AES-128, пустой вариант.
- HLS seek/sync: demuxed VOD — обе дорожки открыты, `Seeked` и позиции
  проверяются по PTS; слуховая проверка A/V sync и дрейфа — в 5.6
  (на headless-машине звукового устройства может не быть).
- README/примеры компилируются (doc-тесты).
- Память: 10 минут HTTP, ручной замер.
- Кэш: блоки, курсоры, вытеснение, backpressure, seek вперёд/назад,
  ошибка загрузчика, закрытие; лимит памяти 64 МиБ.
- `vgpu`: имя release-бинарника (`CARGO_BIN_EXE_vgpu`), URL/путь из
  аргумента, запуск без аргумента.
- Установщики (вручную, чистая Windows): Inno/MSI — установка, обновление,
  удаление; `where vgpu`; `vgpu "<URL>"` и `vgpu` в новой консоли;
  чужие записи `PATH` сохранены, дубликата нет, без UAC; портативно —
  `register-associations.cmd path` / `path remove`.

Сеть в тестах — только `127.0.0.1:0`.

## 8. Зависимости и лимиты

- `ureq` 3.5.x: `default-features = false`, `features = ["native-tls"]`.
  По умолчанию у `ureq` провайдер `Rustls` и корни `WebPki`; для Windows
  нужны явные `TlsProvider::NativeTls` и `RootCerts::PlatformVerifier`.
- `timeout_resolve`/`timeout_connect` 5 с, `timeout_per_read` 2 с;
  `timeout_global`/`timeout_recv_body` не задаём.
- `http_status_as_error(false)`; `max_redirects(10)`.
- Заголовки: `User-Agent: vgpu-player/<version>`, `Accept: */*`,
  `Accept-Encoding: identity`, `Range`. `Referer`/`Cookie` не шлём.
- `tiny_http` — только dev-dependency; `tokio`/`axum` не нужны.
- Лимиты: окно 2 МиБ (этап 3), кэш 64 МиБ, блок 256 КиБ, read-ahead
  8 МиБ, простой 15 с, открытие ≤ 30 с.
- HLS: без новых crate; ISO-8601 для `PROGRAM-DATE-TIME` — свой мини-парсер.
  Плейлист ≤ 4 МиБ, окно сегментов ≤ 32 МиБ на дорожку, обновление live не
  чаще 1 с. Prefetch: 16 с эфира, но ≤ 8 сегментов; 8 соединений (для
  demuxed — по 4 на дорожку). Один `ureq`-агент и те же таймауты/повторы,
  что у HTTP.
- `PATH`: установщики пишут только `HKCU\Environment`; значение не длиннее
  2047 символов (Inno предупреждает, MSI — документированное ограничение).
  Портативная сборка реестр окружения автоматически не меняет;
  `register-associations.cmd path` — только по явной команде.
- `file://` поддерживается; слайдер без перемотки выключается.

## 9. Риски и ограничения

- Кастомный IO может быть медленнее прямого файла — замер на этапе 1,
  иначе для файлов остаётся прямой путь.
- Два читателя дают два соединения и возможное дублирование трафика —
  этап 4 закрывает это общим кэшем (§2.6); если кэш не оправдается —
  рассматриваем один FFmpeg-демуксер.
- Один поток ядра: блокирующее чтение видео может опустошить звук
  (лечится очередью 32, затем prefetch/раздельные декодеры).
- Нет TLS в FFmpeg — `https` только через свой клиент.
- Без `Range` нет перемотки; MP4 с `moov` в конце открывается дольше.
- `Pause`/`Seek` во время чтения задерживаются до 2 с.
- Ресурс может измениться между `Range`; в v1 без гарантии консистентности.
- HLS demuxed live: окна и PTS видео/аудио могут расходиться; выравнивание
  по `PROGRAM-DATE-TIME`/live-edge, проверка на YouTube/Twitch в 5.5/5.6.
  Fallback — muxed-only + ошибка для раздельных дорожек.
- HLS live: обновление плейлиста и `DISCONTINUITY` могут давать короткий
  разрыв; допустимый лаг фиксируется в 5.6.
- HLS-сегменты занимают память окном (≤ 32 МиБ на дорожку); VOD-перемотка
  переоткрывает декодеры и может дать паузу до нескольких секунд.
- HLS-сегменты качаются синхронно в потоке ядра: долгая загрузка может
  задержать тик и плашку `Buffering` до её завершения, а звук — опустеть.
  Асинхронный prefetch — кандидат на 5.5/этап 6; до него ограничение
  фиксируется в `CURRENT_TASK.md`.
- YouTube watch URL не поддерживается; для live нужен master (или две
  ссылки), `yt-dlp -g` даёт отдельные media-плейлисты. `googlevideo` может
  быть недоступен из-за DPI — приёмка на Twitch/Apple/rtbcdn.
- `PATH` пользователя может быть у лимита (2047 символов в реестре):
  Inno предупреждает, MSI не расширяет; уже открытые консоли не видят
  новое значение до перезапуска.
- Release `vgpu` — GUI-подсистема: из консоли команда возвращает
  управление сразу и не печатает stderr; ошибки — в окне плеера.
- Что не обещаем: DRM, YouTube watch URL, DASH, LL-HLS, AES-128 в первой
  версии, ABR, субтитры, офлайн-кэш, авторизацию.
