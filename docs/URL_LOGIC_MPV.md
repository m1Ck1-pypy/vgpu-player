В основе логики просмотра видео по URL в mpv лежит принцип **унифицированного конвейера**. Плеер не делает различий между локальным файлом и сетевым адресом на уровне ядра. Вместо этого он абстрагирует любой источник данных через **потоковый уровень (Stream Layer)**, который затем передаёт данные демультиплексору и далее по стандартной цепочке декодирования и вывода.

Вот как устроен этот процесс шаг за шагом.

### 🧩 Уровень потоков (Stream Layer): Абстракция любого источника

Ключевой элемент — структура `stream_t`. Она представляет собой универсальный интерфейс для чтения байтов, навигации (seek) и управления состоянием, независимо от того, откуда поступают данные: с диска, из памяти или по сети.

- **Единый реестр (`stream_list[]`)**: В mpv зарегистрирован набор драйверов потоков (`stream_info_t`). Каждый драйвер отвечает за свой тип источника (например, `stream_file.c` для файлов, `stream_curl.c` для HTTP/HTTPS).
- **Выбор драйвера по URL**: Когда пользователь передаёт URL, mpv анализирует его схему (префикс `http://`, `file://` и т.д.) и выбирает соответствующий драйвер из реестра. **mpv никогда не угадывает**, является ли строка сетевым адресом; протокол должен быть указан явно.

### 🌐 Обработка сетевых URL (HTTP/HTTPS и другие)

Для сетевых протоколов используется специализированный драйвер **`stream_curl.c`**, который опирается на библиотеку **libcurl**.

- **Производительность и контроль**: libcurl обеспечивает высокопроизводительную работу с HTTP/HTTPS, FTP и другими протоколами. Потоковый уровень через этот драйвер управляет сетевыми запросами, буферизацией и обработкой перенаправлений (redirects).
- **Кэширование**: Данные, полученные по сети, могут проходить через кэш потокового уровня (stream cache) для сглаживания неравномерности сети. В статусной строке mpv отображается объём данных в этом кэше (`Cache: 2s+134KB`).
- **Другие протоколы**: Помимо HTTP/HTTPS, поддерживаются `smb://` (Samba), `ftp://` и множество других, часто через libcurl или встроенные реализации.

### 📦 Демультиплексор: Извлечение потоков из контейнера

Как только поток открыт, управление переходит к **демультиплексору**. Его задача — определить формат контейнера (например, MKV, MP4, TS) и извлечь из него элементарные потоки (видео, аудио, субтитры) в виде пакетов (`demux_packet`).

- **Определение формата**: Функция `demux_open()` перебирает зарегистрированные демультиплексоры (`demuxer_desc_t`), чтобы найти подходящий для данного потока.
- **Основной демультиплексор**: Для большинства форматов используется `demuxer_desc_lavf`, который является обёрткой над библиотекой **FFmpeg (libavformat)**. Именно FFmpeg берёт на себя тяжёлую работу по разбору контейнеров.
- **Работа в отдельном потоке**: Демультиплексор mpv работает в выделенном потоке, чтобы операции ввода-вывода (особенно сетевые) не блокировали воспроизведение.

### 🎬 Дальнейший конвейер воспроизведения

После демультиплексора пакеты попадают в стандартный конвейер mpv, который уже не зависит от того, был ли источник локальным или сетевым:

1.  **Декодер (Decoder Wrapper)**: Пакеты декодируются в кадры (видео) или сэмплы (аудио) с возможным аппаратным ускорением.
2.  **Фильтры (Filters)**: Кадры и сэмплы проходят через цепочку фильтров (масштабирование, конвертация цветового пространства, аудиоэффекты).
3.  **Вывод (Output)**: Готовый видеокадр передаётся видеовыходу (`vo`), а аудиосэмплы — аудиовыходу (`ao`).

### ⚙️ Особые случаи и расширения логики URL

- **Скрипты и внешние резолверы (например, yt-dlp)**: Для сайтов вроде YouTube mpv не загружает видео напрямую. Он использует внешние скрипты (часто `ytdl://` или хуки), которые вызываются перед открытием потока, чтобы получить прямой URL на медиафайл. Затем этот прямой URL передаётся в стандартный потоковый уровень.
- **Хуки (Hooks)**: mpv позволяет вмешиваться в процесс загрузки. Хук `on_load` может быть вызван прямо перед открытием потока, что позволяет динамически изменять URL, добавлять HTTP-заголовки (например, для авторизации) или перенаправлять запрос на другой источник.
- **Пользовательские протоколы**: Через API `mpv_stream_cb_add_ro` можно зарегистрировать собственный протокол (например, `myproto://`) и связать его с функцией-обработчиком на C, Python или другом языке. Это позволяет mpv читать данные из произвольного источника, который вы реализуете.

Таким образом, логика просмотра по URL в mpv — это чёткое разделение ответственности: потоковый уровень абстрагирует «откуда брать байты», а демультиплексор и декодер — «как их интерпретировать и превратить в видео и звук».
