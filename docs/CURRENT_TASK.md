## Задача

Настройки плеера должны переживать перезапуск. Решение владельца: файл хранится
у пользователя, в `%APPDATA%`, а не рядом с exe.

## Что сделано (что менять осторожно)

- **`crates/player-gpui/src/settings.rs`** (новый, приватный модуль): `Settings
{ autoplay, stats_visible, auto_hide, volume }`, `Default` — текущие
  умолчания. Формат — `ключ = значение` (`#` — комментарий), без новых
  зависимостей: `parse`/`to_text` — свободные функции на десяток строк.
  Неизвестные ключи, строки без `=` и значения неверного типа пропускаются,
  `volume` клампится в `0..=1`. `load` при отсутствии/порче файла даёт
  умолчания (порча — с `warn`), `save` создаёт каталог.
- **Путь**: `Settings::default_path()` — `%APPDATA%\vgpu-player\settings.cfg`;
  если `APPDATA` нет — `XDG_CONFIG_HOME` или `~/.config` (Linux-сборка в CI).
  `None` — каталог не определить, тогда настройки живут только в памяти.
- **`app.rs`**: у `PlayerWindow` два новых поля — `settings_path` и
  `saved_settings` (снимок того, что уже лежит в файле). В `new` настройки
  читаются и применяются **до** `open` (иначе `autoplay = false` не успел бы
  подействовать), поэтому плеер создаётся как `cx.new(VideoPlayer::new)` →
  `set_autoplay`/`set_stats_visible`/`set_volume` → `open(path)`.
  `save_settings` собирает текущий снимок и пишет файл только если он отличается
  от `saved_settings`; вызывается сразу после переключения пунктов меню (autoplay,
  оверлей, автоскрытие), сразу после шага громкости колесом и по отпусканию
  ползунка громкости (окно получает `on_mouse_up` и на любой клик — лишних
  записей нет благодаря сравнению).
- **Громкость сохраняется сразу (исправление после проверки владельцем)**:
  первая версия писала файл только через 1,5 с после колеса (по таймеру плашки)
  и не писала после перетаскивания ползунка — дочерний слайдер успевал снять
  `volume_scrubbing` в своём `on_mouse_up` раньше, чем корневой обработчик
  спрашивал его значение. Теперь сохранение не зависит ни от таймера, ни от
  флага перетаскивания; на клик по окну запись не происходит (снимок совпадает).
- **`video_player.rs`**: `set_volume` запоминает значение и без открытого ядра
  (раньше игнорировал), а `open` отправляет новому ядру
  `Command::SetVolume(engine_volume())` — с учётом `mute`. Побочный, но нужный
  эффект: смена файла больше не сбрасывает громкость к 100 %.
- **`lib.rs`**: `mod settings;` — модуль намеренно приватный, публичный API не
  расширялся. Потребитель библиотеки хранит настройки сам, как и раньше.

## Как проверить

```bash
cargo run -q -p player-app            # меняем настройки в меню «⋯»
taskkill /IM player-app.exe /F 2>nul  # закрыть окно
type %APPDATA%\vgpu-player\settings.cfg
cargo run -q -p player-app            # настройки на месте
```

1. Снять галочку «Запускать сразу», открыть файл, закрыть плеер, запустить
   снова с файлом — видео стоит на паузе; в файле `autoplay = false`.
2. Включить оверлей статистики и автоскрытие, перезапустить — галочки и
   поведение те же.
3. Колесо: один шаг (±1 %) — сразу после него в файле уже новое `volume`
   (без ожидания плашки). Перетаскивание ползунка — новое значение появляется
   в файле по отпусканию мыши.
4. Клик по кадру или повторное переключение пункта меню файл не переписывают
   (проверить по времени изменения файла).
5. Перезапуск с громкостью 40 % — 40 % уже до открытия файла; смена файла
   внутри сессии уровень не сбрасывает.
6. Удалить `settings.cfg` — вернулись умолчания (autoplay вкл., оверлей выкл.,
   автоскрытие вкл., громкость 100 %).
7. Испортить файл (`volume = abc`, мусорные строки) — плеер играет, остальные
   ключи читаются, `volume` = умолчание.

## Известные ограничения (актуальное)

- Каждый шаг громкости колесом — отдельная запись файла (~120 байт): так
  «сохраняется сразу»; батчинга нет. Ползунок пишет один раз на отпускание.
- `mute` не сохраняется: после перезапуска звук включён (громкость — та, что
  была до выключения).
- Настройки общие для портативной и установленной копий: файл привязан к
  пользователю, а не к каталогу.
- `embed_in_app` и другие свои окна на `VideoPlayer` файл не читают: это
  поведение обёртки `run_app`.
- Настройки — не JSON/TOML: при добавлении сложных значений (списки, вложенность)
  формат придётся менять.
