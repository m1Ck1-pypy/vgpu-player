## Как проверить сделанное в окне

```bash
# окно без файла: кнопка Play открывает диалог, работают O, меню и перетаскивание
cargo run -q -p player-app

# окно с файлом из аргумента
cargo run -q -p player-app -- assets/test/sync_test.mp4

# примеры библиотеки; DLL нужны и рядом с exe примеров
cp .tools/vcpkg/installed/x64-windows/bin/*.dll target/debug/examples/
cargo run -p player-gpui --example minimal -- assets/test/sync_test.mp4
cargo run -p player-gpui --example embed_in_app -- assets/test/sync_test.mp4
# или из корня: just example-minimal / just example-embed

# портативная папка: запускать двойным кликом из Проводника
dist/vgpu-player/player-app.exe

# два выбранных установщика (оба per-user, без UAC)
dist/vgpu-player-0.1.0-setup.exe         # Inno Setup 7
dist/vgpu-player-0.1.0.msi               # WiX v3 MSI
```

Запускать **без прав администратора** — иначе Windows не отдаст файлы при
перетаскивании (см. «Drag-and-drop»).

Ожидаемо:

- в панели: play/pause, динамик, ползунок громкости и кнопка fullscreen
  справа от него; после конца файла вместо play — стрелка по кругу; поверх
  последнего кадра — круглая кнопка со стрелкой «Повторить»; кнопки
  «Открыть» нет;
- `O` (и `Ctrl+O`) открывает системный диалог; выбранный файл показывает
  превью первого кадра и начинает играть по `Space`;
- для файла без видео вместо кадра — иконка ноты и надпись «Аудио файл»;
  надписи «готов к воспроизведению» больше нет;
- панель управления лежит поверх кадра, а не под ним: при наведении/скрытии
  по автоскрытию видео не сжимается и не растягивается, фон панели
  полупрозрачный (кадр просвечивает);
- при перетаскивании файла появляется подсказка «Отпустите файл, чтобы
  открыть»; после отпускания файл играет (каталоги и отсутствующие пути
  игнорируются, неподдерживаемый файл даёт экран ошибки с «Повторить»);
- кнопка «⋯» в правом конце панели (после кнопки fullscreen) открывает меню

  «Открыть…», «Информация о файле» (только когда файл открыт), «Скрыть

  становится «рукой»;
- время в нижней панели и в «Информации о файле» — `чч:мм:сс`

- `Esc` сначала закрывает меню/инфо-панели, а если ничего не открыто —

- клик по кадру ставит видео на паузу и продолжает его; клик по меню или

- постоянного процента громкости в панели нет: кнопка fullscreen занимает

### Этап 9 — исправление клика по панели (2026-11-18)

- **Симптом:** нажатие на любую кнопку нижней панели (звук, fullscreen,
  «⋯», громкость) заодно переключало воспроизведение; play/pause
  срабатывал дважды и внешне не менял состояние.
- **Причина:** в GPUI `hitbox.is_hovered()` истинно для всех хитбоксов под
  курсором, а не только для верхнего (`hit_test.hover_hitbox_count =
ids.len()`). Панель — наложение поверх полноэкранного `div` «клик по
  кадру» с `on_click`, и клик доходил до обоих. Меню «⋯» уже гасило всплытие
  на `on_mouse_down`, а сама панель — нет.
- **Исправление:** `controls_panel` в `app.rs` получил
  `.on_mouse_down(MouseButton::Left, |_, _, cx| cx.stop_propagation())`.
  Родитель регистрирует мышиные обработчики раньше детей (paint родителя идёт
  до paint детей), в bubble-фазе дети идут первыми и успевают записать свой
  клик, а затем панель гасит всплытие до области кадра. Теперь кнопки в панели
  не трогают воспроизведение; клик по промежутку панели тоже не играет
  роль «клика по кадру».
- Новые release-бинарники и установщики **не пересобирались** (по просьбе
  владельца); проверены только `fmt`, `clippy -D warnings` и
  `cargo test --workspace` (46 / 31 / 8).

### Этап 9 — кнопка fullscreen и подсказки громкости (2026-11-18)

- **Иконки:** в `icons.rs` добавлены `Icon::Fullscreen` (уголки наружу) и

- **Кнопка в панели:** в `controls.rs` постоянный `div` с процентом (40 px)

  теперь получает `&mut Window` (а не только `&mut App`), поэтому кнопка
  сама зовёт `Window::toggle_fullscreen`.
- **Состояние fullscreen:** в `VideoPlayer` добавлено публичное поле
  `fullscreen` с `fullscreen()` и `set_fullscreen()` (по аналогии со
  `stats_visible`). Демо-окно в `render` синхронизирует его из
  `Window::is_fullscreen()`: платформа (Windows-бэкенд `gpui-fast`) меняет
  режим асинхронно, поэтому после клика флаг выставляется оптимистично, а
  затем уточняется по фактическому состоянию. `F` и `Esc` работают как
  раньше.
- **Процент по наведению:** у `VideoPlayer` появилось `volume_hover:
Option<f32>`; `on_mouse_move` ползунка громкости обновляет его через
  `ratio_at(volume_bounds, x)`, `on_hover(false)` очищает. `controls_view`
  рисует подсказку абсолютно над ползунком — панель и кадр не
  перевёрстываются. Процент считается `volume_percent` (округление и кламп
  в целые проценты).
- **Плашка после колеса:** у `PlayerWindow` появилось `volume_notice:
Option<(f32, Instant)>`; после шага колеса, если громкость/mute реально
  изменились, плашка с процентом рисуется в правом нижнем углу над панелью
  (`right(16)`, `bottom(CONTROLS_HEIGHT)`). Живёт `VOLUME_NOTICE_DURATION`
  = 1,5 с, срок проверяет тот же тик автоскрытия (250 мс), видна и при
  скрытой панели. Шаг остался 1 %, mute снимается.
- **Тесты:** `volume_percent_rounds_and_clamps` (0/42/43/100, кламп),
  `volume_hint_follows_the_cursor_and_stays_on_the_slider` и обновлённый

  `cargo test --workspace` (46 в ядре, 31 в UI, 8 doc-тестов: добавился пример
  синхронизации fullscreen из README) — чистые. Ручная проверка в окне —

### Этап 9 — управление мышью и Esc (2026-11-18)

- **`Esc` в fullscreen:** `close_overlays` теперь возвращает `bool`; если
  меню/инфо-панели не были открыты, `Esc` вызывает
  `Window::toggle_fullscreen`. Сначала закрываются панели, вторым нажатием —
  выход из fullscreen.
- **Клик по кадру:** `video_view` обёрнут в `div` с `on_click`, который зовёт
  `VideoPlayer::toggle_playback`. Если клик закрыл меню/панели, он только
  закрывает их (`skip_next_click`), а не ставит паузу. Кнопка «Повторить»
  внутри `video_view` гасит всплытие (`stop_propagation`).
- **Колесо мыши:** `on_scroll` на корне окна меняет громкость шагами ровно по
  1 % (`volume_after_step`, счёт в целых процентах), клампит 0–100 и снимает
  mute. Направление: вверх — громче. Тест
  `wheel_steps_volume_by_one_percent`.

### Этап 9, шаг 2 — исправление после проверки владельцем

Симптом был: «пункты меню не работают». По временному логу было видно, что
меню открывается, а на клик по пункту приходит только «клик мимо меню».

**Настоящая причина — в семантике GPUI:** `hitbox.is_hovered()` возвращает
`true` для **всех** хитбоксов под курсором, а не только для верхнего
(`Window::hit_test` ставит `hover_hitbox_count = hit_test.ids.len()`), а
`on_mouse_down`/`on_mouse_up` регистрируются глобально (`window.on_mouse_event`)
и сами фильтруются этим предикатом. Отсюда два тупика:

1. Список рисовался абсолютно за границами кнопки — мышь в него не попадала.
2. Прозрачная подложка на всё окно («клик мимо закрывает») всегда «наведена», поэтому
   перехватывала клики по самим пунктам — ровно то, что видно в логе.

Та же ловушка была и без подложки: `handle_video_click` висит на области
кадра, а попап лежит поверх неё — клик по пункту закрывал меню на mouse down,
и `on_click` уже не срабатывал.

**Как сделано сейчас:**

- `menu_panel()` — слой `.absolute().top_0().left_0().size_full()` внутри
  области кадра (тот же приём, что у оверлея с кнопкой «Повторить»: точный
  размер, предсказуемая раскладка), внутри — `flex_column`, `items_end`,
  `justify_end`; список — **обычный flex-ребёнок** (280 px, автовысота),
  без абсолютного позиционирования;
- у списка и у каждого пункта на mouse down — `cx.stop_propagation()`, чтобы
  «клик по кадру» не закрывал меню до `on_click`;
- закрытие: `Escape`, выбор пункта, клик по кадру вне списка.

Временные `debug`-логи, добавленные ради этой отладки («меню переключено»,
«клик мимо меню», «меню: …»), удалены 2026-11-17 — остались только логи
перетаскивания, которые были в коде с шага 1.

Клика в панели управления (слайдеры, громкость) меню не закрывает — это
осознанно: иначе оно терялось бы при работе со слайдером.

## Drag-and-drop: как это работает и где ломается

**Итог 2026-11-17: причина найдена, перетаскивание работает.** Владелец
запустил приложение из обычного (неповышенного) терминала — drag-and-drop
заработал. Лог успешного сценария:

```
DEBUG player_gpui::app: файлы над окном
DEBUG player_gpui::app: файлы отпущены над окном count=1
 INFO player_gpui::video_player: файл открыт в UI path=...
```

**Ограничение Windows.** UIPI не передаёт OLE-перетаскивание из Проводника
(средний уровень целостности) процессу с повышенными правами (высокий
уровень). То есть «запуск от имени администратора» drag-and-drop не включает,
а **ломает**. Запускать нужно без повышения прав — включая терминал/редактор,
из которого идёт `cargo run` (на машине владельца терминал был High).

**Что есть в коде для этого случая:**

- проверка прав и плашка **удалены 2026-11-17** по просьбе владельца — теперь
  про ограничение напоминает только эта документация;
- при перетаскивании показывается подсказка «Отпустите файл, чтобы открыть»
  (`on_drag_move::<ExternalPaths>`, `on_file_drop_exit`), `on_drop` висит и
  на корне, и на самой подсказке;
- `debug`-логи: «файлы над окном», «файлы отпущены над окном» (с числом
  путей), «перетаскивание отменено».

**Если drop снова не работает:**

1. перезапустить без прав (проверить, что и терминал/редактор запущен
   обычно): `Win+R` → `powershell` → `cd path\to\vgpu-player` →
   `cargo run -p player-app`;
2. подсказки нет → события не доходят: проверить, что тащат из Проводника
   (архиваторы/браузеры могут не отдавать `CF_HDROP`), и прислать лог;
3. подсказка есть, отпускание молчит → разбирать gpui: прислать лог и
   версию Windows;
4. в логе `файлы отпущены`, файл не играет → смотреть строку об ошибке
   открытия.

**Известный шум.** При открытии Opus-файлов FFmpeg печатает в stderr
`Could not update timestamps for skipped samples` — это его внутреннее
предупреждение про pre-skip, на воспроизведение не влияет.

## Иконки: что есть

| Иконка            | Где используется                               |
| ----------------- | ---------------------------------------------- |
| `play`            | панель, когда воспроизведение остановлено      |
| `pause`           | панель во время воспроизведения                |

## Известные ограничения

- **Плейлиста нет — так решено** (2026-11-17): диалог и drop открывают один
  файл (первый), переключения между файлами нет.
- **Позиция просмотра не восстанавливается** — тоже по решению владельца.
- Перетаскивание файлов не работает, если процесс запущен с правами
  администратора (UIPI). Плашка-предупреждение убрана по просьбе владельца
  (2026-11-17); подробности — в разделе «Drag-and-drop» выше и SPEC §11.14.
- Имя открытого файла в нижней панели не показывается: теперь оно в пункте
  меню «Информация о файле».
- Кнопки «Открыть» в панели нет (убрана по просьбе владельца 2026-11-17):
  файл открывается клавишей `O`, пунктом меню или перетаскиванием.
- Превью — только первый кадр, без выбора: если у ролика начало чёрное
  (затемнение), превью тоже будет чёрным.
- Панель управления лежит поверх кадра и закрывает нижние ≈52 px картинки;
  её высота зашита в `CONTROLS_HEIGHT` (60 px с зазором) — при смене
  отступов панели константу надо править.
- В горячих клавишах нет модификаторов: `shortcut` смотрит только на клавишу,
  поэтому `Ctrl+O` и `O` дают одно действие.
- Текст на кнопках заменён иконками: подписи видны только скринридеру
  (`aria_label`), подсказок при наведении у кнопок нет; подсказка с процентом
  есть только у ползунка громкости.
- Подсказка громкости обновляется по движению мыши: если раскладка сменилась
  под неподвижным курсором, она появится после первого движения.
- Признак fullscreen (`VideoPlayer::fullscreen`) — копия состояния окна, а не
  его источник: демо-окно синхронизирует его в `render`, потому что Windows-
  бэкенд `gpui-fast` меняет режим асинхронно. Потребитель `controls_view`
  должен делать то же в своём `render` (см. `crates/player-gpui/README.md`).
- Меню «⋯» управляется только мышью: стрелки/`Tab` по пунктам не ходят,
  галочка — текстовый «✓», а не системный чекбокс.
- Пока меню открыто, клик по панели управления (слайдеры, громкость) меню не
  закрывает — так решено, чтобы оно не терялось во время работы со слайдером.
- В GPUI `is_hovered` истинно для всех хитбоксов под курсором, а не только
  для верхнего, поэтому полноэкранную подложку под попапом делать нельзя —
  она перехватывает клики (SPEC §11.15). По той же причине панель управления
  гасит всплытие `on_mouse_down`: иначе клики по её кнопкам доходили до
  области «клик по кадру» и переключали воспроизведение (исправлено
  2026-11-18).
- Настройки (`stats_visible`, `auto_hide_enabled`) живут в памяти процесса:
  файла конфигурации нет, после перезапуска всё по умолчанию.
- Замеры CPU/RSS сделаны в CLI; загрузка BGRA в GPU-текстуру видна только в
  окне (SPEC, раздел 13).
- Иконка вшита в exe; при замене `assets/icon.png` надо пересобрать
  `assets/app-icon.ico` и release (SPEC §15.4).
- Установщики per-user: Inno ставит в
  `%LOCALAPPDATA%\Programs\vgpu-player`, MSI — в
  `%LOCALAPPDATA%\vgpu-player`. Пути разные сознательно: MSI с промежуточным
  `Programs` не проходит ICE64 без удаления общего каталога.
- WiX не входит в git: компилятор лежит в `.tools/wix`. На новой машине его
  надо скачать заново (SPEC §15.2).
- Inno Setup 7.1.1 на этой машине печатает `Non-commercial use only`:
  для коммерческого распространения нужна лицензия Inno Setup или NSIS; MSI
  этого ограничения не несёт.
- Тега `v0.1.0` нет: в репозитории нет ни одного коммита.
- В release-exe нет консоли (`windows_subsystem = "windows"`), поэтому
  `println!`/`tracing` в терминал при запуске из Проводника не видны. Для
  диагностики используйте debug-сборку (`cargo run -p player-app`) — там
  консоль остаётся.
- `dist/vgpu-player/` — артефакт, а не исходники: после обновления FFmpeg
  или `cargo clean` папку нужно пересобрать (SPEC §15.1).
- Для запуска примеров DLL FFmpeg нужны и в `target/debug/examples/`: cargo
  кладёт exe примеров туда, а не в `target/debug/`.

## Сборка из Git Bash

В `PATH` может первым оказаться `/usr/bin/link.exe`, тогда сборка падает с
`extra operand …rcgu.o`:

```bash
RUSTFLAGS="-Clinker=rust-lld" cargo test --workspace
```

Doc-тестам нужен ещё и `RUSTDOCFLAGS`: rustdoc линкует отдельно.

```bash
RUSTFLAGS="-Clinker=rust-lld" RUSTDOCFLAGS="-Clinker=rust-lld" \
  cargo test --workspace
```

Release-бинарнику нужны те же DLL, что и debug:

```bash
cp target/debug/*.dll target/release/
```

Установщики из Git Bash (из корня репозитория):

```bash
# Inno Setup 7
"/c/Program Files/Inno Setup 7/ISCC.exe" installer/vgpu-player.iss

# MSI (WiX 3.14.1 в .tools/wix)
mkdir -p target/wix
.tools/wix/candle.exe -arch x64 -dSourceDir=dist/vgpu-player \
  -o target/wix/ installer/vgpu-player.wxs installer/AppFiles.wxs
.tools/wix/light.exe -ext .tools/wix/WixUIExtension.dll \
  -pdbout target/wix/vgpu-player.wixpdb \
  -o dist/vgpu-player-0.1.0.msi \
  target/wix/vgpu-player.wixobj target/wix/AppFiles.wixobj
```

Для `msiexec` в Git Bash нужен `MSYS2_ARG_CONV_EXCL="*"`, иначе `/i` и `/x`
превращаются в пути:

```bash
MSYS2_ARG_CONV_EXCL="*" msiexec.exe /i dist/vgpu-player-0.1.0.msi /qn
```

Подробности — `docs/SPEC.md`, раздел 12.4 и 15.2.
