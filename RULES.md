# RULES

Видеоплеер на Rust с UI на GPUI. Проект учебный: главная цель — чтобы я (владелец) понимал каждую строку и научился Rust, а не просто получил готовый плеер.

## Цель проекта

Плеер локальных видеофайлов со звуком и плавной картинкой: play/pause, перемотка, громкость, полноэкранный режим. Платформы: уточняются в процессе (по умолчанию разрабатываем на той ОС, где запущен агент).

## Как работать со мной (правила для агента)

1. **Один этап за раз.** Не переходи к следующему этапу, пока я явно не скажу, что текущий принят.
2. **Сначала план, потом код.** Перед изменением кода коротко опиши, что собираешься сделать и какие файлы затронешь. Жди моего «ок» для всего, что больше ~50 строк.
3. **Объясняй новое.** Если вводишь концепцию Rust, которую мы ещё не использовали (lifetimes, `Arc`, `Atomic*`, трейты, каналы, `Send`/`Sync`, `Pin` и т.д.), дай 2-4 предложения: что это и почему здесь именно это. При ошибках компилятора объясняй причину, а не только чини.
4. **Ключевые части я пишу сам.** Аудио-часы, очередь кадров, логика перемотки (epoch) — сначала предложи скелет с `todo!()` и комментариями, пусть реализацию я попробую написать сам; потом сделай ревью. Рутину (UI-разметка, обработка ошибок, тесты, boilerplate) можешь писать целиком.
5. **Небольшие коммиты.** Один этап — одна ветка (`stage-N-...`), коммиты маленькие, сообщения на английском в стиле `feat(core): ...`, `fix(gpui): ...`.
6. **Не добавляй зависимости без согласования.** Новый крейт — только после того, как назовёшь причину и альтернативу.
7. **Не переписывай чужой код «заодно».** Только то, что относится к текущей задаче. Если видишь проблему рядом, скажи о ней, но не правь без разрешения.
8. **Честность важнее скорости.** Если не уверен в API GPUI/ffmpeg/rodio, скажи об этом и проверь по docs.rs или исходникам, а не угадывай.
9. **Ничего не запускай и не устанавливай глобально** (системные пакеты, `sudo`, изменение конфигов вне репозитория) без моего разрешения.

## Структура репозитория

```
Cargo.toml                 # workspace
crates/
  player-core/             # движок: demux, decode, A/V-синхронизация. БЕЗ зависимости от GPUI
  player-gpui/             # БИБЛИОТЕКА UI: VideoPlayer, video_view, controls_view (без main)
  player-app/              # бинарник: тонкий main поверх player-gpui
  player-cli/              # консольный запуск ядра для отладки и тестов
assets/test/               # тестовые файлы (см. ниже)
docs/                      # заметки по архитектуре и решениям
```

Принцип: `player-core` ничего не знает об UI. UI общается с ядром только через команды и события.

## Архитектура

```
demux thread ─► audio decode ─► rodio (ведущие аудио-часы)
             └► video decode ─► ограниченная очередь кадров ─► UI забирает кадр по часам

UI ──команды──► ядро:   Open, Play, Pause, Seek(Duration), SetVolume(f32), Stop
UI ◄──события── ядро:   DurationKnown, PositionChanged, NewFrame, Buffering, Ended, Error
```

Ключевые правила дизайна:

- **Ведущие часы — аудио.** Позиция = число реально отданных в устройство сэмплов (`AtomicU64`), а не таймер. Видео подстраивается под аудио. Для файла без звука используется запасной монотонный таймер.
- **Видеодекодер за трейтом** (`VideoDecoder`), чтобы можно было заменить backend (ffmpeg-next, другой) без переписывания остального.
- **Очередь кадров ограничена** (3-6 кадров). Никаких неограниченных каналов для кадров.
- **UI-поток никогда не блокируется** ожиданием кадров или IO. Он только забирает готовое.
- **Перемотка использует epoch (номер поколения):** после seek всё, что пришло со старым epoch, отбрасывается.
- **Перерисовка только при новом кадре или смене состояния**, без перерисовки «на всякий случай».
- Все таймстемпы приводятся к одной единице (`Duration`) на границе ядра.

## Стек и зависимости

- GPUI через `gpui-fast` (подключён как `gpui = { package = "gpui-fast", ... }`). Не смешивать с upstream `gpui` или `gpui-pre` в одном workspace.
- Звук: `rodio` (вывод) + `symphonia` (демукс и аудиодекодеры). `cpal` напрямую не подключаем: версия должна совпадать с версией у rodio.
- Видео: `ffmpeg-next` 8 (нужны dev-библиотеки FFmpeg 8).
- Общее: `crossbeam-channel`, `thiserror` (библиотеки), `anyhow` (бинарники), `tracing`, `clap`.
- Все версии заданы в `[workspace.dependencies]` корневого `Cargo.toml`; в крейтах используем `dep.workspace = true`.
- Зависимости подключаем по этапам (см. ниже), а не все сразу.

## Команды

```bash
cargo build --workspace
cargo test --workspace
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p player-cli -- assets/test/sync_test.mp4
cargo run -p player-app --release -- assets/test/sync_test.mp4
```

Перед каждым коммитом должны проходить `cargo fmt --all --check`, `clippy -D warnings` и `cargo test`. Плеер проверяй в `--release`: в debug декодеры слишком медленные (в workspace стоит `opt-level = 3` для зависимостей, но это не заменяет release для финальных проверок).

## Тестовые файлы

Держи их в `assets/test/` (крупные файлы не коммитим, добавляем в `.gitignore` и описываем, как сгенерировать):

```bash
# видео со счётчиком кадров и писком раз в секунду, для проверки A/V-синхронизации
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 \
       -f lavfi -i "sine=frequency=1000:beep_factor=4" \
       -t 30 -c:v libx264 -pix_fmt yuv420p -c:a aac assets/test/sync_test.mp4
# то же в WebM (VP9 + Opus)
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 -f lavfi -i "sine=frequency=1000" \
       -t 30 -c:v libvpx-vp9 -c:a libopus assets/test/sync_test.webm
# только звук и только видео (для проверки запасных часов)
```

Нужно также несколько «плохих» файлов: пустой, обрезанный, файл с неподдерживаемым кодеком, файл без звука, файл без видео.

## Стиль кода

- Edition 2024. Без `unsafe`, кроме явно обоснованных мест (FFI к ffmpeg), с комментарием `// SAFETY:`.
- Ошибки: `thiserror` в `player-core` и `player-gpui`, `anyhow` только в бинарниках. Без `unwrap()`/`expect()` в рабочем коде (в тестах можно).
- Публичный API ядра: небольшой и документированный (`///`). Внутренности скрыты за `pub(crate)`.
- Каналы и атомики вместо `Mutex` там, где это естественно; если используешь `Mutex`, объясни почему.
- Комментарии объясняют «почему», а не «что». Все комментарии и документация на русском, идентификаторы на английском.
- Тесты рядом с кодом (`#[cfg(test)]`) для логики (синхронизация, очередь, epoch, преобразование времени); интеграционные тесты в `tests/`.

## Известные ловушки (напоминание себе и агенту)

- Позицию воспроизведения нельзя брать у rodio «на глаз»: нужен собственный счётчик отданных сэмплов.
- PTS аудио и видео бывают в разных временных базах; приводить к `Duration` сразу.
- Не блокировать UI-поток; очередь кадров ограничена, иначе память растёт.
- Сборка `ffmpeg-next` ломается чаще всего: нужны dev-библиотеки FFmpeg 8 и `pkg-config`.
- В GPUI загрузка кадров на Windows/Linux идёт через картинку с BGRA и стоит дорого на 4K; на macOS может быть нулевое копирование (проверять в нужной версии gpui-fast).
- Не смешивать две версии `cpal` и два GPUI (`gpui-fast` и upstream) в одном workspace.
